# DSH 0.2.0-rc.1 适配实施计划

> 使用 `superpowers:executing-plans` 逐项执行，并用定向测试验证宿主契约。

**目标**　让 `0.2.0-rc1` 分支的 Mail Assistant 在 DSH `0.2.0-rc.1` 上安装并使用。

**设计**　`docs/superpowers/specs/2026-11-26-dsh-0.2.0-rc1-design.md`

**技术栈**　Node.js、npm、Cordis 4.0、DSH 插件和 Web 客户端。

### Task 1 对齐安装和依赖

**文件**　`package.json`、`package-lock.json`、`src/errors.js`、`tests/unit/manifest.test.js`、`tests/unit/core.test.js`。

- [x] 让 manifest 测试断言 DSH 目标和已发布的 `dsh-llm`、`dsh-credentials`、`dsh-home-paths`、`dsh-tools` peer 均为 `0.2.0-rc.1`，在原分支依赖上观察失败。
- [x] 对齐 Cordis `~4.0.4`、Schemastery `~3.18.4` 与发行版依赖，替换 `HarnessError` 的导入，刷新 npm lockfile。执行 `npm ci` 和定向测试，验证错误类型、错误码与可重复安装。

### Task 2 保留会话启用和隐私边界

**文件**　`src/scope.js`、`src/tools/index.js`、`index.js`、`tests/unit/scope.test.js`、`tests/unit/tools.test.js`。

- [x] 将投影替身改为 `register(def) => dispose` 和 `stateOf(session, key)`，验证首轮 inbox、历史 `user/message`、独立会话和注销。工具测试按 `register(def)`、`agent.ctx.tools.restrict({ deny })` 和 `tools.guard` 检查启用前后、后台调用和卸载。
- [x] 新入口注入 `agents`。在 `registerExchangeTools(ctx, { tools, scope })` 注册工具及守卫，关联 `agent/created`、`session/event`、`agent/disposed` 与已存在的 agent。会话启用后解除其限制。保留系统提示的会话检查和 Web 服务的可选注入。
- [x] 运行 scope/tools 定向测试，验证无 Web 服务时也可加载。使用真实 host 验证门控在 native 和 PTC 能力视图中生效。
- [x] 根据复核修复授权来源。对继承的事件和模型初始委派先观察回归失败，再使用 rc.1 的 `inheritedEventCount` 和子会话 UI `source.rpcId` 验证权限。提升投影缓存版本。

### Task 3 验收 Web 和分发

**文件**　`client.js`、`tests/unit/routes-client.test.js`、`scripts/build-ews.mjs`、`src/ews/connection.js`、`package.json`、`package-lock.json`、`README.md`、`README.zh-CN.md`。

- [x] 根据 rc.1 slot 注册测试移除新版 `settings.section.icon` 注册，验证其余入口、侧栏切换与 `@mail` 候选。
- [x] 更新双语安装说明，在源码安装示例选择 `0.2.0-rc1`，使用 `npm ci` 并说明为 Web profile 安装。
- [x] 原版 rc.1 加载 tarball 时拒绝 `punycode/`。构建 EWS SDK 的单文件分发与许可证声明，再运行已存在的离线 HTTPS／NTLM／SOAP 协议测试。
- [x] 确认指定 DSH clone 检出且版本与 tag 一致。运行 `npm test`、`git diff --check` 和 `npm pack`，在隔离的 rc.1 profile 安装新包并查看插件配置层。
- [x] 通过 ego lite 检查真实客户端的三个入口、紧急锁定切换、操作历史和输入候选。核对真实凭据服务只返回配置状态，检查通过宿主信任校验的 API 和拒绝路径。
- [x] 复核全分支改动与验证记录，将适配提交留在本地 `0.2.0-rc1`。

## 实际验证

- `npm ci` 生成 EWS 分发文件及许可声明。`npm test` 通过 51 项。`npm run test:integration` 通过本地 HTTPS／NTLM／gzip／SOAP 流程，真实企业 Exchange 项按环境配置跳过。
- DSH `0.2.0-rc.1` 在隔离的 Web profile 中通过 tarball 和源码目录两种装配。验证首次启用、独立会话、恢复、fork 与子代理授权边界、PTC 工具列表和卸载。
- ego lite 验证侧栏、设置、插件详情、紧急锁定、凭据状态、历史页及 `@mail` 候选插入。Web 状态和历史 API 对已授权请求返回 200，未认证请求返回 401，不受信来源返回 403。

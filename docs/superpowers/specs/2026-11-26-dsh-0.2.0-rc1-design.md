# DSH 0.2.0-rc.1 适配设计

在 `0.2.0-rc1` 分支交付 Mail Assistant 1.4.0 的 DSH `0.2.0-rc.1` 适配。保留 15 个 Exchange 工具、草稿和软删除限制、文件夹策略、紧急锁定、设置与操作历史。依据 `dsh-v0.2.0-rc.1`（`4878cdabd87d4041bdaff61d04c966883b9fd07a`）的公开插件接口。

## 方案

本分支使用 rc.1 的原生接口。统一跨版本兼容会额外维护两套投影与工具可见性机制。单独调整依赖声明也无法保留 `@mail` 的会话行为，因为 rc.1 的 `tools.register` 只接受工具定义。

## 宿主与客户端契约

- 组合包只声明 DSH `0.2.0-rc.1`。使用该发行版的 DSH peer 和 Cordis、Schemastery 版本线，从 `@deepseek-ai/dsh-llm` 继承 `HarnessError`，保留既有错误码。
- 使用 `sessionProjections.register(definition)` 返回的注销函数和 `sessionProjections.stateOf(session, key)`。沿用投影键、版本和事件契约，使首轮消息和历史恢复都能启用会话。
- 在宿主注册 15 个定义。用 rc.1 的 agent 作用域 `tools.restrict({ deny })` 隐藏尚未启用的邮箱工具，在匹配的用户消息入队时解除。`tools.guard` 对缺少会话授权的调用拒绝执行。初始化已存在的 agent，并释放监听、限制和工具注册。系统提示按会话投影显示。
- 保留 Web 路由的宿主请求校验、凭据存储和状态、审计、操作历史文件格式。Web 与 headless 使用现有组合包入口。
- 保留设置页、插件详情、侧栏入口和 `@mail` 候选。rc.1 的 `settings.section` 只承载设置页及标签，图标由侧栏入口提供。
- 构建时打包现有 EWS SDK 和依赖，附带许可证声明。rc.1 的 profile 加载器无法解析 `tough-cookie` 的 `punycode/`，打包后保持宿主和 EWS 源码版本受锁文件约束。

## 验收

测试使用现有脱敏样例和隔离的 DSH home。用指定源码目录确认检出的版本，以该发行版 CLI 安装实际 tarball 并启动 Web。用 ego lite 核对设置、紧急锁定、操作历史、侧栏和 `@mail`。在宿主运行时验证未启用会话、首轮启用、已启用会话和恢复会话的可见性及拒绝行为。

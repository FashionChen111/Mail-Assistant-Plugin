# Mail Assistant 适配 DSH 0.2.3-alpha.2

## 目标和验收

从插件 `main` 的 v1.4.0 建立 `0.2.3-alpha.2` 分支，交付可安装到 DSH 0.2.3-alpha.2 的源码和插件包。验证真实 DSH 中的插件安装、Web 配置与历史界面、会话触发和 headless 装配。保留邮箱权限、仅保存草稿、凭据和历史数据格式。Exchange 测试使用本地 TLS/NTLM/EWS 替身。

## 方案

以 DSH `dsh-v0.2.3-alpha.2` 源码为契约，使用该版本的公开投影、工具、提示词、Web 路由与凭据服务。现有 HTTP 路径和浏览器组件可以继续使用。共享 Fetch 路由也提供认证，但会改变请求路径和处理协议。分支独立发布契约，因此选用 WebServer 的原生路由认证，清单声明精确 DSH 版本。

- Node.js 采用宿主要求 `^24.22.3 || >=26.13.1`。EWS 沿用锁定版本。复用 rc.1 的构建脚本预打包 EWS 和许可证声明，绕开目标加载器处理 EWS 间接依赖 `punycode/` 时的解析错误。
- 路由声明 `auth: required`，只接受认证后的 owner。状态、凭据、应急锁定、历史和主体大小限制沿用现有处理。
- 工具注册仍从 `agent.session` 判断权限。系统提示词从宿主提供的 `session` 判断同一投影。
- 投影按本会话自有事件识别 `@mail`。继承事件、代理转发和共享访客消息不授予访问。子代理要求有用户 RPC 标记，也覆盖旧会话中曾被记录成 `user` 的代理委派。提升投影缓存版本，由 DSH 重放旧记录。

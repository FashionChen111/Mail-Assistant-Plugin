# Mail Assistant DSH 0.2.3-alpha.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `0.2.3-alpha.2` 分支交付适用于 DSH 0.2.3-alpha.2 的 Mail Assistant。

**Architecture:** 从 v1.4.0 迁移宿主入口契约。投影统一判定工具与提示词，宿主 WebServer 统一验证 HTTP 请求，原有 Exchange 处理保留在插件中。

**Tech Stack:** Node.js、npm 锁文件、Cordis、Zod、DSH WebServer、EWS/NTLM、ego lite。

**Spec:** [适配设计](../specs/2026-11-27-dsh-0.2.3-alpha.2-design.md)

## Global Constraints

- DSH `0.2.3-alpha.2`，Node.js `^24.22.3 || >=26.13.1`。
- 保留邮箱权限、仅保存草稿、凭据和历史数据格式。
- Exchange 测试使用本地 TLS/NTLM/EWS 替身。

## Review Focus

- 未登录、跨站和非 owner 请求都无法读取或更改配置与历史。
- 首轮 inbox、后续消息和重新打开的会话能正确识别当前会话中的用户触发。
- fork 的继承事件及子代理中的旧委派内容不会启用邮箱。
- 打包依赖能由目标宿主加载，headless profile 可独立装配。
- 浏览器三个入口、快捷入口状态和 `@mail` 补全可操作。
